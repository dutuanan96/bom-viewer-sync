## GitHub Data Flow

Current read path:
- `fetchCloudPayload()` prefers GitHub Contents API raw with cache-bust:
  `https://api.github.com/repos/<owner>/<repo>/contents/<path>?ref=main&t=<timestamp>`
- Uses header `Accept: application/vnd.github.raw`.
- Falls back to `raw.githubusercontent.com`.

Current admin save path:
- `writeGithubData(token)` calls `syncLegacyBom()`.
- Builds normalized payload.
- Calls `fetchGithubFile(token)` to get current GitHub `data.js` payload and SHA from Contents API.
- Computes changes with `describePayloadChanges(remoteFile.payload, payload)`.
- Prepends notification with `appendNotificationEvent(payload, { changes })`.
- PUTs through `buildGithubUpdateRequest()`.

This is intentional. Do not change it back to comparing only `this.state.loadedPayload`, because stale admin tabs/cache can otherwise produce generic notifications.

## Cache Notes

The user correctly observed that GitHub raw has cache delay. Current mitigation:
- Viewer/admin read via Contents API raw first, not raw GitHub.
- URL includes `?t=<timestamp>`.
- Admin shell uses bumped script versions: `data.js?v=22`, `app-core.js?v=23`, `app-admin.js?v=21`.

If admin still saves generic notifications, first suspect the user is running old cached `admin.html`/`app-core.js`. Ask them to close/reopen admin or Ctrl+F5.
